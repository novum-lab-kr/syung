# 슝 — 수도권 대중교통 출퇴근 앱 계획서

작성 2026-09-27 · 기반: 이 레포의 실시간 노선도(https://syung.nol-meok.cloud)

## 1. 한 줄 요약

로그인한 사용자가 자주 하는 이동(출근·퇴근 등)을 저장해 두면, 그 시간에 **현재 위치에서 지하철·버스·도보를 섞은 가장 빠른 경로**를 계산하고, **"10분 뒤 열차가 오니 지금 나가세요"** 처럼 출발 시점을 알려 주는 앱.

## 2. 이름·브랜드

| 항목 | 내용 |
|---|---|
| 이름 | **슝** (영문 Syung). 빠르게 슝~ 가는 소리. 이름만으론 무슨 앱인지 안 보여서 스토어·검색에선 "슝 · 수도권 출퇴근" 처럼 부제를 붙임 |
| 주소 | https://syung.nol-meok.cloud (웹 지도) |
| 로고 | 노란 사각 타일 + 검은 캡슐(열차) + 헤드라이트 점 + 왼쪽 속도선. 파일은 `web/brand/` (앱·스토어 아이콘, 라이트·다크 파비콘, 단색) |
| 메인 컬러 | **슝 노랑 `#FFD400`** + 먹색 `#141414` |
| 보조 컬러 | 남색 `#102F3D` (헤더·앱 바), 다크 모드 바탕 `#0A171D` |

**색 쓰는 규칙**
- 노랑은 **면**(버튼, 알림 배지, 아이콘 타일, 강조 카드)으로 쓰고, 그 위 글자는 먹색. 흰 바탕 위 노란 글자·선은 대비가 낮아서 쓰지 않음.
- 다크 모드에서는 노랑을 글자·아이콘 색으로 써도 됨 (먹색 바탕 위 노랑은 대비 충분).
- 출구 번호 배지는 이미 노랑(`#FFD200`, 지하철 출구 표지판 색)이라 브랜드와 자연스럽게 이어짐. "3번 출구" 안내를 노란 배지로 강조.
- 노선색과 겹치지 않게: 수인분당선(`#F5A200`)·의정부선(`#FDA600`)이 노랑 계열이라, 지도 위 노선·열차에는 브랜드 노랑을 쓰지 않음. 브랜드 노랑은 지도 밖 UI와 "지금 출발" 같은 행동 강조에만.

## 4. 핵심 기능

1. **가입·로그인**
   - 들어오면 지금처럼 수도권 전체 실시간 지도(열차 위치, 역, 출구)가 보인다.
2. **이동 저장 (두 가지 방식)**
   - **도착 기준:** 도착지 + 도착 시각 (예: 평일 회사, 09:00까지)
   - **출발 기준:** 출발지 + 도착지 + 출발 시간대 (예: 평일 08:00~08:20 집 → 회사)
   - 요일 반복, 이름(출근·퇴근), 켜고 끄기
3. **가장 빠른 경로 안내**
   - 현재 위치 기준으로 지하철·버스·도보 조합 경로
   - 단계별 안내 예시:
     > 08:12 군자역 7호선 (장암 방면) 탑승 → 건대입구 하차 → **3번 출구** → 도보 2분 → 000 정류장 302번 버스 → 00 정류장 하차 → 도보 4분 → 08:51 도착
   - 실시간 도착 정보로 시간표를 보정해서 표시
4. **출발 알림**
   - 저장한 시간대가 되면 "10분 뒤 7호선 도착, 지금 출발하세요"
   - 지연·운행 변동 시 다시 알림 (예: "다음 열차로 바꾸면 3분 늦어요")

## 5. 지금 있는 것 / 새로 필요한 것

| 구성 요소 | 상태 | 비고 |
|---|---|---|
| 지하철 실시간 위치·역별 도착 | ✅ 있음 | 서울시 실시간 도착 API, 90초 캐시 프록시 |
| 지하철 노선·역·시간표 | ✅ 있음 | KTDB GTFS (라이선스 확인 필요, 8장) |
| 역 출구 번호·위치 | ✅ 있음 | OSM, 630개 역 · 2,996개 출구 |
| 선로 형태·역 크기 | ✅ 있음 | OSM + 출구 기반 보정 |
| 실시간 지도 (웹) | ✅ 있음 | MapLibre WebGL, 3D 건물·그림자·테마 |
| 자동 배포 | ✅ 있음 | GitHub Actions → 서버 |
| **경로 계산 엔진** | ❌ 필요 | GTFS + OSM 도보망 기반 (6장) |
| **버스 노선·정류장·시간표** | 🔶 부분 | KTDB GTFS에 전국 버스 포함 |
| **버스 실시간 도착** | ❌ 필요 | 서울·경기·인천 버스 정보 API (지역마다 다름) |
| **도보 경로** (출구 ↔ 정류장) | 🔶 부분 | OSM 보행 도로 |
| **회원·저장 서버** | ❌ 필요 | 로그인, 저장 이동, 기기 토큰 |
| **알림** | ❌ 필요 | 앱 푸시 (FCM / APNs) |
| **앱** | ❌ 필요 | 지도·경로·설정 화면 |

## 6. 구조 (초안)

```
[앱 iOS/Android] ──► [API 서버] ──► [경로 계산 엔진]  ← GTFS(지하철+버스) + OSM 도보망
      ▲                  │                ▲
      │ 푸시             │                │ 실시간 보정
      │                  ▼                │
  [FCM/APNs] ◄── [알림 스케줄러] ──► [실시간 수집기]  ← 지하철(서울시) · 버스(서울/경기/인천)
                         │
                    [DB: 회원, 저장 이동, 기기]
```

- **경로 계산 엔진:** 직접 만들기보다 검증된 오픈소스(예: OpenTripPlanner)에 GTFS와 OSM을 넣는 방식을 먼저 검토. 수도권 전체 규모에서 속도·메모리 확인 필요.
- **실시간 수집기:** 지금 프록시처럼 **사용자 수와 상관없이** 노선·지역 단위로 모아서 호출 (API 한도 보호).
- **알림 스케줄러:** 저장 이동마다 출발 시간대 전에 경로를 다시 계산하고, 알림 시점을 정해 푸시.
- **앱 지도:** 지금 웹 지도를 앱 안에서 재사용할지(웹뷰), 네이티브 지도(MapLibre Native)로 옮길지 1단계에서 결정.

## 7. 단계별 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0. 선행 확인** | KTDB 이용허락, 버스 API 키 발급(서울·경기·인천), 서울시 API 한도 증설 | 상업 이용 가능한 데이터 확보 |
| **1. 지하철 경로 시범** | 지하철만으로 A역 → B역, "몇 분 열차 → 몇 시 도착", 출구 안내 | 실측 이동과 도착 시각 오차 ±3분 이내 |
| **2. 버스 추가** | 버스 시간표 + 실시간 도착, 환승·도보 포함 경로 | 출구 → 정류장 도보 안내까지 |
| **3. 앱 뼈대** | 앱 프로젝트, 로그인, 지도 화면, 경로 검색 화면 | 테스트 기기에서 경로 검색 |
| **4. 저장 이동** | 출근·퇴근 저장, 요일 반복, 저장 경로 화면 | 저장한 이동의 오늘 경로 표시 |
| **5. 알림** | 출발 알림, 지연 재알림 | 실제 출근길에서 알림 수신 |
| **6. 출시 준비** | 성능, 개인정보 처리방침, 스토어 등록 | 스토어 심사 제출 |

## 8. 위험 요소 · 미리 풀어야 할 것

1. **KTDB GTFS 라이선스 (가장 중요)**
   - 공공누리 4유형(출처표시·상업적 이용 금지·변경 금지). 별도 이용허락을 받으면 상업 이용 가능.
   - 대안: 공공데이터포털의 지하철·버스 시간표 자료로 대체 (수집·정리 작업 필요).
2. **실시간 API 한도·조건**
   - 서울시 지하철 API는 키당 하루 1,000회. 운영용 한도 증설 필요. 상업 이용 조건 확인 필요.
   - 버스 실시간 API는 서울·경기·인천이 제각각이라 각각 신청·연동 필요.
3. **정확도**
   - 시간표만으로는 "10분 뒤 도착" 안내가 틀릴 수 있음 → 실시간 보정 필수.
   - 지하철 실시간 기록은 실제보다 20초~1분 늦게 들어옴 (실측).
4. **위치·개인정보**
   - 현재 위치, 집·회사 위치는 민감 정보. 저장 최소화, 처리방침, 동의 절차 필요.
5. **알림 신뢰성**
   - 앱이 꺼져 있어도 제때 와야 함 → 서버 쪽 스케줄러에서 계산해 푸시.
6. **서버 한 대 구조**
   - 지금은 서버 한 대. 사용자가 늘면 경로 엔진·수집기 분리, 모니터링 강화 필요.
